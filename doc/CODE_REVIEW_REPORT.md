## 1. 安全问题分析

### 🔴 XSS (跨站脚本攻击) 漏洞

**问题描述**: 项目中多处使用`v-html`指令直接渲染用户输入内容，存在严重的XSS攻击风险。

**影响文件**:

- `components/forum/Comment.vue:102` - 评论内容渲染
- `components/MarkdownEditor.vue:205` - Markdown预览
- `pages/quiz.vue:24,100,189` - 测试题目内容

**风险等级**: 🔴 严重

**具体问题**:

```vue
<!-- 危险的v-html使用 -->
<div class="comment-content" v-html="finalContent" />
<div class="preview-content" v-html="renderedHTML" />
<div v-html="formatQuestionText(currentQuestion.text)" />
```

**解决方案**:

1. 使用DOMPurify库对所有HTML内容进行清理
2. 实现内容安全策略(CSP)
3. 对用户输入进行严格验证和转义

```javascript
// 推荐的安全实现
import DOMPurify from 'dompurify'

const sanitizedContent = computed(() => {
  return DOMPurify.sanitize(props.content, {
    ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'code', 'pre'],
    ALLOWED_ATTR: [],
  })
})
```

### 🔴 认证和授权缺陷

**问题描述**:

1. Token存储在localStorage中，容易受到XSS攻击
2. 缺少Token过期处理机制
3. 没有实现CSRF保护

**影响文件**:

- `stores/userStore.js` - 用户状态管理
- `plugins/axios.js` - HTTP拦截器
- `api/user.js` - 用户API

**解决方案**:

1. 使用HttpOnly Cookie存储敏感Token
2. 实现Token刷新机制
3. 添加CSRF Token验证
4. 实现更严格的权限控制

### 🔴 敏感信息泄露

**问题描述**:

1. 硬编码的API服务器地址暴露在客户端
2. 调试信息可能泄露敏感数据

**影响文件**:

- `nuxt.config.ts:67` - 硬编码服务器地址
- `plugins/axios.js:8` - 硬编码API地址

```typescript
// 问题代码
vite: {
  server: {
    proxy: {
      '/api': {
        target: 'http://120.76.138.103:5050/', // 硬编码服务器地址
        changeOrigin: true,
        rewrite: path => path.replace(/^\/api/, ''),
      },
    },
  },
}
```

**解决方案**:

1. 使用环境变量管理API地址
2. 移除生产环境的调试信息
3. 实现配置文件分离

## 2. 代码质量问题

### 🟡 ESLint警告过多

**统计结果**: 137个警告，主要包括:

- 未使用的变量: 45个
- Console语句: 28个
- v-html安全警告: 4个
- 其他代码质量问题: 60个

**主要问题文件**:

- `components/Graph/` - 图形组件中大量未使用变量
- `pages/quiz.vue` - 复杂组件缺少拆分
- `test/` - 测试文件中大量console语句

**解决方案**:

1. 清理所有未使用的变量和导入
2. 移除或替换console语句为适当的日志系统
3. 修复所有ESLint警告

### 🟡 组件复杂度过高

**问题描述**:

- `pages/quiz.vue` (683行) - 单个文件过大
- `components/MarkdownEditor.vue` (1011行) - 功能过于复杂
- `components/Navbar.vue` (598行) - 导航组件职责过多

**解决方案**:

1. 拆分大型组件为多个小组件
2. 使用组合式API重构复杂逻辑
3. 实现关注点分离

### 🟡 缺少类型定义

**问题描述**:

- 大部分文件使用`.js`而非`.ts`
- 缺少TypeScript类型定义
- Props和事件缺少类型约束

**解决方案**:

1. 迁移到TypeScript
2. 添加完整的类型定义
3. 使用接口定义数据结构
